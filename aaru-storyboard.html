1. Agent Construction
"How do you build a single synthetic person?"
CURRENT

LLM-as-Agent

Prompt an LLM with a demographic profile + trait bundle. Agent "is" the LLM conditioned on its persona card. Behavior = LLM completion.
Pro: Rich, flexible, handles novel scenarios. Con: Stochastic, expensive at scale, consistency issues ("embers").
CURRENT

Classical ML Agent

Statistical model (logistic regression, random forest) predicts behavior from demographic features. Deterministic, fast.
Pro: Fast, reproducible, well-understood. Con: Can't handle novel scenarios, no reasoning.
OPPORTUNITY SAM

Hierarchical Bayesian Agent

Each agent = individual posterior drawn from population prior via partial pooling. Agent parameters are probability distributions, not point estimates.
Pro: Principled uncertainty, borrows strength across agents, updates with new data. Con: Computationally expensive, needs careful prior specification.
→ This is Serif's engine. NumPyro + NUTS. Individual posteriors from cohort priors.
FRONTIER

Hybrid: LLM + Bayesian Backbone

LLM generates rich behavior, Bayesian model constrains it to be distributionally plausible. LLM proposes, statistical model disposes.
Pro: Best of both — richness + consistency. Con: Architecture complexity, latency.
→ The researcher role description: "hybrid LLM + classical social science architectures"
2. Population Architecture
"How do you build a million agents that look like a real population?"
CURRENT

Top-Down Demographic Allocation

Start with census distributions (age, race, income, geography). Sample agents to match known marginals. Assign traits from conditional distributions.
Pro: Matches aggregate stats perfectly. Con: Assumes independence between traits, misses correlational structure.
OPPORTUNITY SAM

Partial Pooling Across Subgroups

Hierarchical model where agent parameters are drawn from subgroup-level distributions, which are themselves drawn from population-level distributions. Captures correlational structure naturally.
Pro: Handles sparse subgroups, uncertainty propagates correctly. Con: Requires careful model specification.
→ Direct PRISM architecture: archetypes as cluster centers, individuals as draws from archetype distributions.
OPPORTUNITY

Microsimulation Uplift

Start with real microdata (ACS PUMS, CPS) and "uplift" — add synthetic traits that aren't in the original data but are plausible given what is.
Pro: Grounded in real data. Con: Limited by what surveys measure.
FRONTIER

Generative Population Model

Train a generative model (VAE, diffusion) on microdata. Sample new populations that are statistically indistinguishable from real ones but fully synthetic.
Pro: Can generate populations for places/times with no data. Con: Validation is hard — how do you know the fake population is realistic?
3. Behavior Simulation
"Given an agent with traits, how do you predict what they do?"
CURRENT

LLM Completion

Ask the LLM: "Given this person's profile, how would they vote / respond to this scenario?" The LLM's output IS the behavior.
Pro: Handles open-ended scenarios. Con: No ground truth calibration, hallucination risk.
OPPORTUNITY SAM

Disposition → Behavior DAG

Explicit causal graph: traits → dispositions → context → behavior. Each edge is a parameterized function. Behavior is downstream inference, not LLM generation.
Pro: Interpretable, counterfactual-capable, consistent. Con: Requires domain expertise to specify the DAG correctly.
→ PRISM's L1→L2→L3→[CA]→L4 architecture. Already built.
OPPORTUNITY

Discrete Choice Models

Multinomial logit / mixed logit. Agent evaluates utility of each option and picks the highest. Well-studied in economics.
Pro: Theoretically grounded, fast. Con: Assumes rational utility maximization, which is often wrong.
FRONTIER

Reinforcement Learning Agents

Agents learn behavior through interaction with environment. Policy updates based on rewards. Emergent behavior rather than specified behavior.
Pro: Captures adaptation, learning, strategic interaction. Con: Reward specification is hard, computationally expensive, hard to validate.
4. Environment Modeling
"What world do the agents live in?"
CURRENT

Static Scenario Injection

Define a scenario (election, policy change, crisis) and ask agents to respond. Environment is a fixed prompt, not dynamic.
Pro: Simple, controllable. Con: No feedback loops, no agent-agent interaction.
OPPORTUNITY

Agent-Agent Interaction

Agents influence each other. Social networks, information cascading, norm formation. One agent's vote changes another agent's calculus.
Pro: Captures contagion, polarization, tipping points. Con: Combinatorial explosion, hard to validate.
OPPORTUNITY

Dynamic Environment

Environment evolves over time. Economy changes, candidates drop out, news breaks. Agents re-evaluate as conditions shift.
Pro: Captures temporal dynamics. Con: Need a model of the environment itself, not just agents.
FRONTIER SAM

Exogenous Refraction Layers

Environment modeled as refraction layers ([M] Milieu, [CA] Choice Architecture) that mediate between agent dispositions and behavior. Macro = observable, micro = stochastic.
Pro: Separates what's modelable from what's not. Con: Novel architecture, no established tooling.
→ PRISM's [F]/[M]/[CA] layers. The micro/macro distinction is the key insight.
5. Validation & Calibration
"How do you know the simulation is right?"
CURRENT

Aggregate Benchmarking

Compare simulated election results to actual election results. Does the model get the right winner, right margin, right state-level breakdown?
Pro: Clear success metric. Con: Can be right for wrong reasons (calibrated aggregates, wrong individuals).
OPPORTUNITY SAM

Individual Plausibility Checks

Do individual agents make sense? "Gun-owning vegan environmentalist in rural Alabama" detection. Cross-validation of trait bundles against survey microdata.
Pro: Catches distributional fidelity failures. Con: Expensive, need ground truth at individual level.
→ The "embers" problem Matt described. Directly relevant to the researcher role.
OPPORTUNITY SAM

Posterior Predictive Checks

Generate simulated data from the model, compare to real data. If you can't tell the difference, the model is well-calibrated.
Pro: Bayesian gold standard for model checking. Con: Requires generative model, not just predictive.
→ Standard Bayesian workflow. brms/Stan/NumPyro PPC.
FRONTIER

Counterfactual Validation

Validate on scenarios that didn't happen: "What if candidate X had dropped out?" Compare to natural experiments, quasi-experiments, or historical counterfactuals.
Pro: Tests the model's causal structure. Con: No ground truth for counterfactuals by definition.
6. Temporal Dynamics
"How do agents change over time?"
CURRENT

Snapshot Simulation

Generate a population at a point in time, simulate one event. No persistence, no memory, no evolution.
Pro: Simple, fast. Con: Misses drift, learning, radicalization, disengagement over time.
OPPORTUNITY

Rolling Forward

Same population, rolled forward through time. Agents accumulate experiences, update beliefs. Demographics shift (aging, migration, births/deaths).
Pro: Captures longitudinal dynamics. Con: Error accumulates, drift detection needed.
FRONTIER SAM

Phase Transitions

Most of the time, agents are in steady state (feed-forward DAG). But phase transitions (divorce, war, migration) re-open formative layers and re-refract personality into disposition.
Pro: Captures why people change politics dramatically. Con: Detecting phase transitions is itself a modeling problem.
→ PRISM's feed-forward vs. RL insight. DAG = steady state, RL = phase transitions.
FRONTIER

Generational Simulation

Simulate across generations. Children inherit some traits from parents, refracted through their own formative context. Population evolution over decades.
Pro: Captures long-run political realignment. Con: Speculative, very hard to validate.
